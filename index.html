What is GitHub?

GitHub is a website where people store code, work together, and keep track of changes.

Think of it like Google Drive — but specially designed for coding, with superpowers.

GitHub uses a tool called Git, which acts like a time machine for your code.

Git vs GitHub: Git = the engine (tracks changes locally). GitHub = the website (stores & shares code online).
🧩

Core Concepts

1 Repository (Repo)

A folder on GitHub. Contains your project files, remembers every change ever made, and can be shared with others.

2 Commit

Saving your work with a message. GitHub remembers every commit forever — like checkpoints in a game.

3 Branch

A safe copy of your project to experiment on. Main branch = official. Other branches = testing playground.

4 Merge

When your experiment works, merge the branch back into main. "This change is good — add it to the real project."

5 Pull Request (PR)

A proposal to merge your changes. "Hey team, I made changes — can we add them?" Others review, comment, or approve. Note: it's about merging, not downloading.

6 Clone

Download a repo to your computer. You get a full copy of the project.

7 Push

After making changes on your computer, push them to GitHub. Push = upload your changes.

8 Pull

Download the latest changes from GitHub to your computer.

9 Fork

Your own copy of someone else's repo. Useful to modify, suggest improvements, or keep your own version.

10 Issues

Like to-do tasks or bug reports. Example: "Login button doesn't work", "Add dark mode".

11 README.md

The homepage of your repo. Explains what the project does, how to install it, and how to use it. Written in Markdown.

12 Git

The engine behind GitHub. Can be used via Command Line, VS Code, or GitHub Desktop.

Git Setup & First-Time Config

1

Download & Install Git

Visit git-scm.com and install Git for your OS.

2

Open Git Bash

In your project folder → Right-click → Open Git Bash Here

3

Introduce Yourself to Git

Run these once to configure your identity:

bash — git config
git config --global user.name  "YourGitHubUsername"
git config --global user.email "your-email@example.com"
FlagScope
--localOnly this project folder
--globalAll folders on your account (recommended)
--systemAll users on this PC
4

Initialize Git — run once per project

bash
git init
5

Add Files to Staging

bash — git add examples
git add index.html      # specific file
git add .               # all files
git add folder-name     # all files in a folder
git add *.html          # all .html files
6

Commit Your Changes

bash
git commit -m "Your message describing the changes"
7

Connect to a GitHub Repo — run once per project

First create the repo on GitHub, then connect locally:

bash
git remote add origin https://github.com/YourUsername/your-repo.git
# "origin" = shorthand alias for the full repo URL
8

Create & Name the Main Branch

bash
git branch -M main
# -M = move/rename. "main" is the standard name.
9

Push for the First Time

bash
git push -u origin main
# -u saves origin + branch. Next time just: git push

Daily Workflow Loop

Make Changes
→
git status
→
git add .
→
git commit
→
git push
bash — daily loop
git status                          # see what changed
git add .                            # stage everything
git commit -m "describe the change"   # save checkpoint
git push                             # upload to GitHub
bash — check commits
git log             # full log
git log --oneline    # compact — shows 7-digit hash IDs
🌿

Branching & Merging

bash — create & switch to a branch
git checkout -b branch-name
# Then: add → commit → push (the daily loop)
git push -u origin branch-name
git branch -a

List all branches (local + remote)

git branch -d branch-name

Delete a branch locally

git push origin --delete branch-name

Delete a branch from GitHub too

git checkout main

Switch back to the main branch

git merge branch-name

Merge a branch into the current branch (switch to main first)

bash — full merge flow
git checkout main            # switch to main first
git merge branch-name        # merge branch into main
Changing the Default Branch?
Go to GitHub → Repo Settings → Default Branch and change it there. Then update local Git: git remote set-head origin -a (-a = auto-detect the new default)

Going Back to Previous Versions

Always run git log --oneline first to find the 7-digit hash ID of your target commit.
✅ RECOMMENDED

Method 1 — Safe Checkout

View old code without permanently changing anything, OR copy old code as a new commit — preserves full history.

bash
# View old version in LOCAL (temporary)
git checkout hash-id

# Make old version permanent (copy as new commit)
git checkout hash-id .     # copy to local
git commit -m "Reverted to vX"
git push

This keeps V1, V2, V3 intact — just adds a new commit matching the old version.

⚠️ USE WITH CAUTION

Method 2 — Hard Reset & Force Push

Removes everything after the target commit. Destructive — deletes newer commits permanently.

bash
git reset --hard hash-id-of-v1
git push -f             # force push — overwrites GitHub
❌ NOT RECOMMENDED

Method 3 — Revert (step-by-step)

Reverts one commit at a time. Very confusing and requires extra steps — avoid unless you understand it well.

bash
git revert hash-of-v3    # goes back to V2
git revert hash-of-v2    # goes back to V1
git push
